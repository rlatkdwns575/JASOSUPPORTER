# Career Content Builder Skill

## 목적

이 스킬은 JasoSupporter 앱에서 사용자의 경험과 스펙을 구조화하고, 이를 다음 산출물로 변환할 때 사용한다.

- 경험 카드
- STAR 구조
- 마스터 자소서
- 문항별 자기소개서 초안
- 포트폴리오 프로젝트 설명
- README.md 초안
- 면접 예상 질문
- 기업별 지원서용 요약

이 스킬의 핵심은 글을 대신 꾸며 쓰는 것이 아니라, 사용자가 실제로 경험한 내용을 분석 가능한 구조로 정리하고 재사용 가능한 취업 준비 콘텐츠로 만드는 것이다.

## 핵심 원칙

1. 사용자가 제공한 경험만 사용한다.
2. 없는 성과나 수치를 만들지 않는다.
3. 면접에서 방어할 수 없는 표현을 만들지 않는다.
4. 문항 의도에 맞게 경험을 재구성한다.
5. 자소서, 포트폴리오, 면접 답변은 모두 Experience 데이터를 기반으로 한다.
6. 하나의 경험은 여러 산출물에 재사용될 수 있어야 한다.
7. 부족한 정보가 있으면 보완 질문이나 필요한 추가 정보를 제안한다.
8. 추상적인 표현보다 상황, 행동, 결과를 구체화한다.

## 사용 시점

다음 작업을 할 때 이 스킬을 사용한다.

- 사용자가 경험을 입력했을 때
- 경험을 STAR 구조로 바꿀 때
- 경험에서 역량 태그를 추출할 때
- 자소서 문항에 적합한 경험을 추천할 때
- 마스터 자소서 초안을 만들 때
- 자소서를 첨삭할 때
- 포트폴리오 프로젝트 설명을 만들 때
- README.md를 만들 때
- 면접 예상 질문을 만들 때
- 지원 직무와 경험을 연결할 때

## 입력 데이터

입력 데이터는 가능한 한 다음 구조를 따른다.

### Experience

- title: 경험 제목
- type: 경험 유형
- period: 기간
- organization: 기관/소속
- role: 맡은 역할
- situation: 문제 상황
- task: 해결해야 했던 과제
- action: 내가 한 행동
- result: 결과
- learned: 배운 점
- techStacks: 사용 기술
- competencyTags: 역량 태그
- evidenceLinks: GitHub, 문서, 결과물 링크

### Essay Request

- question: 자기소개서 문항
- targetLength: 글자 수
- companyName: 기업명
- jobTitle: 지원 직무
- tone: 원하는 문체
- selectedExperienceIds: 사용할 경험 id 목록

### Portfolio Request

- projectTitle: 프로젝트명
- targetRole: 지원 직무
- outputType: 포트폴리오 / README / 면접 설명 / Figma 카피
- selectedExperienceIds: 사용할 경험 id 목록

## 경험 구조화 절차

사용자가 자유롭게 경험을 입력하면 다음 순서로 정리한다.

1. 경험의 핵심 사건을 파악한다.
2. 경험 유형을 분류한다.
3. 문제 상황을 정리한다.
4. 사용자의 역할을 분리한다.
5. 사용자가 직접 한 행동만 추출한다.
6. 결과를 정리한다.
7. 배운 점을 정리한다.
8. 관련 역량 태그를 추천한다.
9. 자소서/포트폴리오 활용 가능성을 판단한다.
10. 부족한 정보를 제안한다.

## STAR 변환 절차

경험을 STAR 구조로 변환할 때는 다음 형식을 따른다.

### Situation

당시 어떤 상황이었는지 설명한다.

주의:
- 배경을 너무 길게 쓰지 않는다.
- 문제 상황이 드러나야 한다.

### Task

해결해야 했던 과제나 목표를 설명한다.

주의:
- 팀 전체 목표와 본인의 역할을 구분한다.

### Action

사용자가 직접 한 행동을 설명한다.

주의:
- 가장 중요한 부분이다.
- 추상적인 표현을 피한다.
- "노력했다", "기여했다"보다 구체적인 행동을 쓴다.

### Result

결과와 변화를 설명한다.

주의:
- 수치가 있으면 사용한다.
- 수치가 없으면 정성적 변화로 표현한다.
- 없는 수치는 만들지 않는다.

### Learned

배운 점과 이후 적용 가능성을 설명한다.

주의:
- 직무와 연결 가능한 형태로 정리한다.

## 역량 태그 추천 기준

다음 태그 중 경험에 맞는 것을 추천한다.

- 문제 정의
- 데이터 수집
- 데이터 전처리
- 분석 설계
- 모델링
- 자동화
- 백엔드 구현
- 프론트엔드 구현
- API 연동
- DB 설계
- UI/UX 개선
- 고객 이해
- 서비스 기획
- 실험 설계
- 성과 측정
- 협업
- 갈등 조정
- 문서화
- 발표
- 리더십
- 운영 개선
- 품질 관리
- 트러블슈팅
- 학습 지속성
- 직무 이해
- 산업 이해

## 자소서 생성 절차

자기소개서 초안을 만들 때는 다음 순서로 작업한다.

1. 문항이 묻는 핵심 의도를 분석한다.
2. 문항 유형을 분류한다.
3. 선택된 경험이 문항에 적합한지 확인한다.
4. 경험의 핵심 메시지를 하나로 정한다.
5. 문항에 맞는 구조를 선택한다.
6. 초안을 작성한다.
7. 글자 수를 맞춘다.
8. 과장되거나 방어하기 어려운 표현을 제거한다.
9. 직무와의 연결성을 강화한다.
10. 부족한 정보가 있으면 보완 포인트를 제시한다.

## 자소서 문항 유형

자소서 문항은 다음 유형 중 하나로 분류한다.

### 지원동기

구조:

- 개인적 계기
- 산업/기업 관심
- 직무 연결
- 입사 후 기여

주의:
- 회사 설명만 나열하지 않는다.
- 사용자의 경험에서 출발해야 한다.

### 직무 역량

구조:

- 직무에 필요한 역량 정의
- 관련 경험
- 구체적 행동
- 결과
- 입사 후 활용

주의:
- 기술 스택 나열만 하지 않는다.
- 왜 그 역량이 직무에 필요한지 설명한다.

### 문제 해결

구조:

- 문제 상황
- 원인 파악
- 해결 행동
- 결과
- 배운 점

주의:
- 문제를 어떻게 정의했는지가 드러나야 한다.

### 협업

구조:

- 팀 상황
- 갈등 또는 역할 문제
- 본인의 조정 행동
- 결과
- 협업관

주의:
- 팀 성과와 본인의 행동을 구분한다.

### 도전

구조:

- 도전한 목표
- 어려움
- 지속한 행동
- 결과
- 성장

주의:
- 막연한 열정보다 실제 행동을 보여준다.

### 성장 과정

구조:

- 가치관이 형성된 계기
- 반복된 행동
- 현재 역량과 연결
- 직무 활용

주의:
- 어린 시절 이야기만 길게 쓰지 않는다.

### 입사 후 포부

구조:

- 직무 이해
- 본인의 강점
- 단기 기여
- 장기 성장 방향

주의:
- 추상적인 포부를 피한다.

## 자소서 첨삭 기준

자소서를 첨삭할 때는 다음 기준으로 본다.

1. 문항에 직접 답하고 있는가
2. 경험이 구체적인가
3. 본인의 역할이 드러나는가
4. 결과가 명확한가
5. 직무와 자연스럽게 연결되는가
6. 문장이 너무 길지 않은가
7. 같은 표현이 반복되지 않는가
8. 과장되거나 허위처럼 보이는 표현이 없는가
9. 키워드만 나열하지 않았는가
10. 면접에서 질문이 들어와도 답변 가능한가

## 포트폴리오 생성 절차

포트폴리오 프로젝트 설명을 만들 때는 다음 구조를 따른다.

1. 프로젝트 한 줄 소개
2. 문제 정의
3. 사용 데이터 또는 기술
4. 담당 역할
5. 구현 과정
6. 핵심 기능
7. 트러블슈팅
8. 결과
9. 한계점
10. 개선 방향
11. GitHub 또는 결과물 링크

## 포트폴리오 작성 원칙

- 프로젝트 목적이 먼저 보여야 한다.
- 사용 기술보다 문제 해결 과정이 더 중요하다.
- 본인이 맡은 역할을 명확히 써야 한다.
- 결과가 약하면 한계와 개선 방향을 보완한다.
- 데이터/개발 프로젝트는 파이프라인, 모델, 화면, 배포, 검증 중 무엇을 했는지 구분한다.
- 포트폴리오는 읽는 사람이 빠르게 이해할 수 있어야 한다.

## README 생성 절차

README.md를 만들 때는 다음 구조를 따른다.

1. 프로젝트 제목
2. 프로젝트 한 줄 소개
3. 문제 정의
4. 주요 기능
5. 기술 스택
6. 프로젝트 구조
7. 실행 방법
8. 주요 구현 내용
9. 트러블슈팅
10. 결과 및 배운 점
11. 개선 방향

## 면접 질문 생성 절차

면접 예상 질문은 다음 기준으로 만든다.

1. 자소서에 쓴 주장 검증 질문
2. 프로젝트에서 본인 역할 확인 질문
3. 기술 선택 이유 질문
4. 문제 해결 과정 질문
5. 실패와 개선 질문
6. 결과 검증 질문
7. 직무 연결 질문

예시:

- 이 프로젝트에서 본인이 직접 담당한 부분은 무엇인가요?
- 왜 이 기술을 선택했나요?
- 결과를 어떻게 검증했나요?
- 다시 한다면 무엇을 개선하겠습니까?
- 해당 경험이 지원 직무와 어떻게 연결되나요?

## 출력 형식

작업 결과는 사용 목적에 따라 다르게 출력한다.

### 경험 구조화 출력

- 경험 제목
- 경험 유형
- STAR 정리
- 역량 태그
- 활용 가능한 자소서 문항
- 보완할 정보

### 자소서 출력

- 문항 분석
- 사용한 경험
- 초안
- 글자 수
- 보완 포인트

### 첨삭 출력

- 총평
- 강점
- 문제점
- 수정 방향
- 개선본

### 포트폴리오 출력

- 프로젝트 한 줄 소개
- 문제 정의
- 역할
- 구현 과정
- 결과
- 한계점
- 개선 방향

### 면접 출력

- 예상 질문
- 질문 의도
- 답변 방향
- 꼬리 질문

## 금지사항

다음 작업은 금지한다.

- 허위 경험 생성
- 허위 성과 생성
- 허위 수치 생성
- 기업 정보 임의 추가
- 사용자가 하지 않은 역할 추가
- 기술 스택 조작
- 결과 과장
- 면접에서 방어 불가능한 문장 생성
- 문항과 관련 없는 경험 억지 연결
- 사용자의 원본 경험을 지나치게 미화

## 좋은 결과물의 기준

좋은 결과물은 다음 조건을 만족한다.

- 사용자의 실제 경험에 기반한다.
- 문항이 묻는 바에 답한다.
- 본인의 역할이 분명하다.
- 행동이 구체적이다.
- 결과가 명확하다.
- 직무와 연결된다.
- 과장되지 않는다.
- 재사용 가능하다.
- 포트폴리오와 면접 답변으로 확장 가능하다.

## JasoSupporter 앱에 적용할 때의 주의사항

이 스킬은 JasoSupporter 앱 내부 기능과 연결되어야 한다.

따라서 결과물은 가능한 한 다음 데이터와 연결한다.

- Experience id
- MasterEssay id
- PortfolioProject id
- ApplicationRecord id

AI 답변은 단순 채팅 메시지로 끝나면 안 된다.

가능하면 다음 액션으로 이어져야 한다.

- 경험 카드로 저장
- 자소서 문항에 적용
- 새 버전으로 저장
- 포트폴리오 프로젝트로 변환
- README 초안으로 변환
- 면접 질문으로 변환
